# 和导师讨论研究方向

进入研究生生活差一个星期就两个月了，这期间了解了一下组内毕业相关事宜，并查找阅读了一些论文，思路仍然不是很清晰。

<!-- more -->

## 组内毕业条件概况

从学长和导师咨询了下，组内是需要发一篇小论文，具体发到什么期刊并没有什么要求，但组内大部分都是 3/4 区。

把小论文投出去后，才可以准备开题，所以这个小论文还是很重要的。

毕业论文的方向和小论文的研究方向大致是一样的，其中可以添加导师给出的横向项目中的内容（如果合适）。

这样的意思是，研二上需要把小论文投递出去，因为研二上需要开题，那必然要在研一下学期结束前把实验做完，得到可用的数据。

## 讨论方向

导师反复强调我们在一个交通型的学校中，研究方向故也要是在交通大类下。

最近看的论文都是 POI 方向的，然后今天汇报，导师说给我一份申报书，再参考这个里面的内容进行查找理解一下。

我的想法是如果确实这个申报书有用，就参考参考，否则，就看 POI 方向算了，反正所谓的研究，在我看来就是达到毕业的目标。

## 论文阅读方法

有了 Agent 的帮助，许多具体的代码实现比以前容易了。对我来说，更难的是判断什么问题值得研究，以及为什么要选某种方法来解决它。我希望读完一篇论文后，自己也能讲清楚这两个判断。

我会先读摘要（Abstract）和引言（Introduction），弄清作者观察到了什么现象，又是怎样把它变成一个具体的研究问题。读引言时，我会优先核对那些支撑研究动机的引用。比如，作者说某个已有方法在特定场景下表现不好，我就回到被引论文和本文的实验里，看有没有人在这个场景下测过、实际结果如何。如果前人只在其他场景做过实验，那么这个方法在新场景下表现如何，仍是一个待验证的问题。

方法部分可以有选择地读。代码细节按需查，但我要弄懂作者为什么这样设计，以及这个设计针对的是前面提到的哪个困难。然后带着这个问题看关键实验，再结合局限性（Limitations），判断结论在哪些条件下成立。

读完后，我希望能用自己的话回答五个问题：

1. 作者观察到了什么现象？
2. 作者怎样把这个现象转化成了一个可以检验的研究问题？
3. 这个问题为什么值得解决？
4. 在相同或可比的条件下，已有方法做到了什么，这篇论文又补上了什么？
5. 作者为什么选择这个方法？哪项结果最能支持这个选择，还有哪些情况有待验证？
