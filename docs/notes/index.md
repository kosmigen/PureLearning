# 学习路线图

这里收录平时的学习笔记。四个分区不是一张并列的科目表，而是一条有先后的路线：先用 Python 把想法写成能跑的代码，再补上语言背后的通用概念，最后把它们用到 AI 和真实项目里。

<div class="grid cards" markdown>

- [**Python**](python/index.md) · 语言本身与标准库，从语法到把想法真正跑起来
- [**计算机基础**](fundamentals/index.md) · 语言背后的通用概念：数据结构、系统、网络与数据库
- [**AI**](ai/index.md) · 从机器学习基础到生成式 AI 的实际应用
- [**工程笔记**](engineering/index.md) · 让代码可测试、可复现、可交付的那些做法

</div>

## 为什么是这个顺序

**Python 在最前。** 它是后面所有内容的表达工具。语法本身不难，难的是把「我知道这个原理」变成「我能写出来并且跑对」——所以这部分记得最多的是实际写过的代码，而不是语法条目。

**计算机基础在中间。** 学到一定量之后，卡住你的往往不再是语言，而是语言背后的东西：为什么这个数据结构更快、进程和线程到底差在哪、一次请求在网络里走了多远。这些概念不依赖某一门语言，值得单独整理并长期复查。

**AI 靠后，但不最后。** 它需要 Python 和基础概念同时到位才好往下走，所以放在路线中段之后。

**工程笔记贯穿全程。** 测试、类型、打包、可复现性——这些不属于某个阶段，而是每一段路上都会反复遇到的问题，所以单独记，按问题归档。

## 笔记怎么写

同一件事记两遍是有意的：**「文章」里放写完的、给别人看的**，**「笔记」里放给自己查的**。笔记不追求完整，只要求下次翻到时能立刻接上。

每篇笔记尽量交代清楚四件事：

| 要交代的 | 说明 |
| --- | --- |
| 问题是怎么来的 | 什么场景下遇到、为什么值得记 |
| 结论和依据 | 原理、成立条件、代价或复杂度 |
| 验证方式 | 用什么代码或实验确认了它 |
| 边界 | 什么情况下这个结论不成立 |

只写结论的笔记，三个月后和搜索引擎的结果没有区别。
