# Java 文档编写规范

本规范用于保持 `docs/notes/Java/` 中的内容风格一致。参考 [Tpoint Tech Java Tutorial](https://www.tpointtech.com/java-tutorial) 的概念介绍、语法、示例、输出与对比表组织方式，正文和示例独立编写。

## 分类与路径

- `index.md`：语言由来、历史、运行方式、版本基准、关键字速查与阅读入口。
- `basics/`：日常编程必需的语法、对象、数据容器、异常与 IO。
- `advanced/`：语言机制、网络、并发与 JVM。
- `framework/`：按具体框架组织配置、机制与应用示例。
- `third-party/`：按具体库组织依赖、API、类型约定与适用范围。

保持已经确定的目录与网址。新增目录使用小写英文和连字符；新增页面及时检查所在目录的 `.nav.yml`。只写一篇内容时，可以直接添加 Markdown 文件，不必额外创建多层目录。

## 统一的讲解方式

专题文章采用以下顺序，可按主题增加必要小节：

1. 用一至两段说明概念和解决的问题。
2. 解释基本语法或核心组成，平行概念优先使用表格。
3. 给出一个完成单一任务的完整示例。
4. 给出固定输出；输出不固定时明确说明预期现象。
5. 解释代码中最关键的两三步。
6. 补充常见操作、边界或对比。
7. 用“注意事项”列出真实容易出错的地方。
8. 给出一个基于当前示例的小练习。
9. 列出实际查阅的主题来源和官方资料。

栏目概览页以概念、阅读顺序和入口为主，不必强行添加完整程序。语法片段允许省略上下文，但要说明前置变量、导入或运行条件。

## 代码与版本

- 当前完整示例以 JDK 21 为基准，不启用预览特性；使用其他版本时单独注明。
- 完整程序使用 `java title="Main.java"` 代码块，并包含导入、类和入口方法。
- 不同示例中的 `Main` 独立保存和运行；存在 `package` 时说明项目目录与启动类名。
- 使用第三方依赖时列出固定版本、完整项目配置和运行命令。
- 输出放在 `text` 代码块中，前面标注“输出”。不要把不稳定的路径、线程顺序或内存数值伪装成固定结果。
- 文件示例优先使用临时目录，并清理示例创建的资源；网络示例优先使用本地服务和系统分配端口。
- 并发示例应等待任务完成再观察最终结果，并解释结果顺序是否确定。
- 完整示例应实际编译运行，核对输出；修改后重新验证受影响的示例。

## 语言与参考资料

正文使用中文短段落，类型、方法和关键字保留英文。先解释，再给例子；避免口号、泛泛的优点列表和重复的结尾总结。

同一概念保持名称一致，例如“流程控制”“集合框架”“异常处理”“文件与 IO”“并发编程”。保留已有专题的边界，通过相对 Markdown 链接连接相关内容。

参考站用于发现知识点和学习讲解形式，不整篇翻译或复制正文、代码和配图。API 行为、版本差异和语言规则以对应版本的官方资料核对。文章末尾的“参考资料”保留可访问的原始链接，不把未阅读的页面列为来源。

## 发布前检查

核对目录、导航和相对链接；编译运行完整示例，确认输出；执行严格构建。若增加了宽表格或新的排版形式，再检查窄屏显示。
